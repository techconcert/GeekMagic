# R3 addendum (lead decisions that override docs/DESIGN-R3.md)

Read after DESIGN-R3.md. Where they differ, this file wins.

1. **Baseline is main as of R2 (recovery rev 4).** R2 renamed/removed things the design mentions: there is no persist.cpp or game save; settings (`GqSettings`) live in `firmware/prefs.*`; the status page has a read-only "Save sector" probe. Check the real code, not the design's assumptions (P-1..P-4). P-4 (plain HTTP to api.open-meteo.com works) is CONFIRMED: the owner got a normal JSON reply with `current.temperature_2m`, `current.weather_code`, `current.wind_speed_10m`, e.g. {"current":{"time":"2026-11-11T10:30","interval":900,"temperature_2m":25.2,"weather_code":3,"wind_speed_10m":14.7}} (use this as a test fixture).
2. **Approved by the owner:** outgoing weather request every 30 minutes; sleep mode (screen off, CPU 80 MHz, WiFi and /update stay on; at the wake time the hero is up and the game resumes fully; the owner does NOT want a 10-minute lit window as a design goal, but keep a safe way to reach the page: WiFi stays on anyway); auto restarts on (A2), WiFi modem sleep off (A3) already in the base.
3. **The sector 0x3FA000 is NOT free** (probe on the owner's clock: first bytes FF5F00FF05000001FFFF5368656E7A68, stock firmware data). NEVER write there. Flash persistence is NOT approved in R3: build the storage layer behind an interface with the RTC backend only (RTC user memory, survives restarts and updates, lost on unplug). A flash backend may come later at a sector the owner approves after a probe; do not implement flash writes, keep every flash-write lint rule and gate as in R2 (no flash write/erase calls anywhere).
4. **No phone backup/restore.** The owner explicitly rejected it. Drop the localStorage restore banner (design 5.4) and everything like it.
5. **Size:** the base .bin is 419,680 B. R3 total budget +26 KB flash cap as in the design; keep the image under 470 KB, and remember float printf/scanf are linked out (lint L9 forbids float formatting/parsing: use integer maths, parse the JSON by hand).
6. Keep the commit rules: any change to a recovery-contract file needs a commit message line `RECOVERY-CHANGE: <why>` and an increment of GQ_RECOVERY_REV in safety.cpp (CI guard). The owner has no serial flasher: the /update page and rescue AP must keep working in every build; never weaken a gate.
